# Данные путеводителя

Сотрудники обновляют данные в ZooKeeper. Rust-сервер путеводителя читает одну публичную выгрузку целиком. Карта, каталог и кормления используют общий снимок. Карта в путеводителе работает в режиме просмотра, в том числе по старым ссылкам на редактор.

## Настройка сервера

| Переменная | Значение |
| --- | --- |
| `PARK_GUIDE_ZOOKEEPER_EXPORT_URL` | Полный HTTPS-адрес выгрузки, доступный серверу путеводителя |
| `PARK_GUIDE_ZOOKEEPER_READ_KEY` | Серверный ключ только на чтение этой выгрузки. Передаётся заголовком `X-API-Key` |

Без адреса выгрузки сервер запускается в демонстрационном режиме с файлами `public/demo`. При подключении сервер проверяет новую выгрузку раз в минуту. Некорректный ответ или ошибка связи сохраняют последний принятый снимок в серверном процессе. Если сервер ещё не получил снимок, он отвечает 503. Открытый путеводитель проверяет снимок раз в минуту, при возвращении на вкладку и после восстановления связи. При потере сети он использует последний сохранённый снимок.

Проверка подключения доступна по `GET /api/health`. Значение `source` показывает `park-files` или `zookeeper`. Версия публикации доступна в `GET /api/v1/guide`, содержимое — в `GET /demo/guide-publication.json`. Адрес ZooKeeper и ключ используются только сервером. Диагнозы и ветеринарные записи остаются в ZooKeeper.

## Контракт выгрузки

Выгрузка должна возвращать один JSON-объект с шестью полями.

| Поле | Формат |
| --- | --- |
| `animals` | Массив публичных карточек с уникальными `slug`, `name`, `category`. Дополнительно допускаются `description`, `scientific` и локальный путь `thumbnail` в `assets/` |
| `places` | Массив мест с `zone` (1 или 2), уникальным в пределах зоны `id` и `name`. Координаты `geo` имеют порядок `[долгота, широта]`. `species` ссылается на `animals.slug`. Допускаются `service`, `detail`, `audioStory`, `legacyId` и `keywords` |
| `mapAlignment` | Привязка технического плана в формате `map-alignment.json`. Положение меток передаётся отдельно в `places[].geo` |
| `enclosures` | Границы в формате `map-boundaries.json` с ключами `зона/id`. Точки нормированы относительно технического плана |
| `visitorPaths` | Гостевые дорожки в формате `map-guest-paths.json` с координатами технического плана |
| `feedings` | Расписание в формате `feeding-programme.json`. События ссылаются на `zone` и `id` места. Поле `species` в публичном ответе содержит один `slug` из каталога. Если выгрузка передаёт список, сервер берёт первый известный `slug`. Для событий без известного вида поле опускается |

Для существующих QR-кодов и аудиорассказов сохраняются идентификаторы видов и мест. Если идентификатор места меняется, прежнее значение можно передать в `legacyId`.
